# Greenfield document-to-symbolic expert system

This change builds document ingestion, structured extraction, deterministic rendering, versioning, execution, API/CLI, React, and container support for Prolog, CLIPS, Z3, and Clingo. The architecture centralizes behavior in `ExpertSystemService` and prevents providers from returning raw engine source. It is not ready to ship because activation certifies checks it never performs, three engines ignore the requested goal, provenance is trusted rather than verified, conflict resolution can accept contradictions, and the advertised container worker boundary does not exist. **Watch for:** **confirmed** invalid artifacts can become active; **confirmed** CLIPS/Z3/Clingo answer program-wide questions instead of the requested goal; **confirmed** accepting both conflict sides disables abstention; **confirmed** engine code retains egress and shares the API/provider process; **likely** Prolog argument construction permits term injection through backslash/quote combinations.

**Verdict**: NEEDS_CHANGES

## High-level view

Generation parses local files into typed IR, but promotes every provider fact, rule, and constraint directly to accepted state. Evidence and `system_axiom` claims are never reconciled with host-ingested source sections.

Activation renders four files and advances through syntax, semantic, and consistency states without invoking engine validators or fixtures. Finalized directories also remain writable and are read without checksum verification.

Routing selects engines by capability, but only Prolog receives a goal. Multi-step plans overwrite prior results rather than carrying dependency output forward.

Conflict handling abstains on directly affected predicates, but detects only narrow exact contradictions. Resolution accepts any non-empty subset—including both sides—and can suppress abstention while restoring contradictory items.

Non-loopback v1 routes require a bearer token, but `/ready` leaks details, generation accepts arbitrary server directories, and the React image has no runtime path to the Compose token. Engine execution remains in-process despite `execution_mode=container`; timeouts abandon threads, and the Compose network is not internal.

Lockfiles and base-image digests are pinned, but OS installers and CI actions float. CI builds the image without starting the authenticated production server, running Compose, validating Prolog, or proving activation gates.

<details><summary>Details</summary>

## Activation records checks it never performs

**High — confirmed.** `validate_and_activate` renders artifacts, unconditionally transitions through `SYNTAX_CHECKED`, `SEMANTIC_CHECKED`, and `CONSISTENCY_CHECKED`, then writes `passed=True`; no engine parser, execution, fixture, or solver check runs (`src/llm_expert_system/lifecycle.py:88-126`). An unsafe Clingo rule with an unbound head variable was reproduced as active with a passing manifest. Run every native engine in validation mode, perform IR type/arity/rule-safety and full constraint checks, persist actual reports, and reject before finalization on unavailable required engines or failures.

**Medium — confirmed.** `Atom.arguments` is unbounded beyond `Scalar`, relation arity is not cross-checked, rule variables are not range-restricted, all Z3 variables become `Int`, and non-finite floats reach `str(value)` (`src/llm_expert_system/models.py:14,131-133`; `src/llm_expert_system/renderers.py:147-178`). Add finite-number constraints, aggregate count/size limits, grounded-fact and rule-safety validation, predicate signatures, and expression sort inference.

## Capability routes do not represent query semantics

**High — confirmed.** `_query_text` is empty for every engine except Prolog (`src/llm_expert_system/lifecycle.py:227-235`). CLIPS returns all resulting facts, Z3 checks global satisfiability, and Clingo enumerates answer sets without comparing the requested predicate/arguments (`src/llm_expert_system/engines.py:76-89,104-122,132-151`). Compile goal-specific constraints/show directives/templates and define consistent answered/unknown/unsat semantics per engine.

**High — confirmed.** Routing creates a dependency chain, but passes no bindings/models/objectives between steps and returns only the last result (`src/llm_expert_system/routing.py:35-46`; `src/llm_expert_system/lifecycle.py:208-224`). `require_proof`, `require_models`, and `optimize` never affect workers (`src/llm_expert_system/models.py:254-261`). Implement typed step inputs/outputs and aggregation, or reject unsupported plans and flags.

## Prolog goal construction crosses the trust boundary

**High — likely.** Prolog queries concatenate caller values and escape apostrophes but not existing backslashes (`src/llm_expert_system/lifecycle.py:227-235`). In SWI quoted atoms, a backslash before the inserted quote can change tokenization; booleans also hit the numeric branch and become `True`/`False` variables. Use MQI parameters or a shared tested serializer that escapes backslashes first, handles booleans before numbers, rejects controls, and never concatenates a caller-controlled goal term.

## Conflict resolution can legalize contradictions

**High — confirmed.** Resolution accepts any non-empty subset of involved IDs, marks selected items accepted, and marks the record resolved (`src/llm_expert_system/lifecycle.py:139-178`). Passing both opposite-fact IDs was reproduced with both facts accepted and `resolved=True`, so later queries stop abstaining. Enforce category-specific invariants, re-run analyzers/solvers, refuse remaining contradictions, and replace synthetic IDs with references to real items.

**High — confirmed.** Detection requires exact fact/rule argument tuples, treats only literal `false` as an unsatisfiable constraint, does not filter rule state, and does not propagate conflicted premises to derived predicates (`src/llm_expert_system/conflicts.py:23-83`; `src/llm_expert_system/lifecycle.py:190-203`). Add solver-backed consistency, state filtering, rule overlap/unification, dependency impact propagation, and cross-engine disagreement checks.

## Provider schema validity is mistaken for provenance

**High — confirmed.** Generation discards extraction metadata and force-copies every provider fact, rule, and constraint to `ACCEPTED` (`src/llm_expert_system/lifecycle.py:56-82`). Acceptance only requires any evidence or provider-controlled `system_axiom=true`; document, locator, excerpt, and hash are never checked against host sections (`src/llm_expert_system/models.py:188-199`). Keep output proposed, forbid provider system axioms, reconcile references against canonical sections, and preserve per-document provider/model/attempt metadata before promotion.

**Medium — confirmed.** Deduplication keeps one relative path per content hash, while file mtime is included as `imported_at` in canonical JSON (`src/llm_expert_system/ingestion.py:60-78`; `src/llm_expert_system/models.py:74-81,245-250`). This loses duplicate-source provenance and makes touching an unchanged file produce a new digest. Preserve source identities over shared blobs and keep timestamps outside semantic version identity.

## Timeouts and container mode provide no worker boundary

**High — confirmed.** `asyncio.to_thread` returns on timeout without stopping the native worker; the semaphore is released while CLIPS/Clingo can continue consuming resources, and output bytes are checked only after full materialization (`src/llm_expert_system/broker.py:54-81`; `src/llm_expert_system/engines.py:76-89,132-151`). Use killable subprocess/container workers, terminate and reap on deadline, stream-count output, and retain admission capacity through cleanup.

**High — confirmed.** `execution_mode` is never consumed (`src/llm_expert_system/config.py:20-29`), so engines share the FastAPI process/environment. Compose hardens that shared container but defines a normal egress-capable bridge, not `internal: true` (`compose.yaml:18-36`), contradicting `README.md:104-113` and `docs/security.md:11-13`. Split no-secret workers onto an internal network or remove the isolation/no-egress claims.

## Non-loopback authentication does not secure the deployed workflow

**High — confirmed.** Compose requires `LLM_EXPERT_API_TOKEN`, while the browser only reads build-time `VITE_API_TOKEN` (`compose.yaml:10-15`; `web/src/api.ts:6-8`), and Docker neither supplies it nor offers runtime configuration (`Dockerfile:5-11,38-40`). The shipped UI can reach public operations routes but gets 401 from every v1 request. Do not bake secrets into JavaScript; provide an interactive session or runtime operator token held only in memory and test the container flow.

**Medium — confirmed.** Unauthenticated `/ready` returns diagnostics including absolute workspace path, active registry record/path, and engine details (`src/llm_expert_system/api.py:100-109`; `src/llm_expert_system/lifecycle.py:237-243`). Protect detailed diagnostics beyond loopback and expose a minimal readiness boolean publicly.

**High — confirmed.** Generation accepts any existing server directory as its import root (`src/llm_expert_system/api.py:27-29,119-124`), so a token grants ingestion access to every readable supported file tree. Accept relative paths only beneath a configured root, reject symlinked components, and cap file count, depth, and aggregate bytes.

## Version identity and immutability do not match lifecycle claims

**Medium — confirmed.** Any matching non-rejected version is returned as unchanged regardless of state, while API/CLI skip activation when unchanged (`src/llm_expert_system/lifecycle.py:83-87`; `src/llm_expert_system/api.py:123-127`; `src/llm_expert_system/cli.py:72-78`). Reproduction left a matching record in `draft` and no active version after a later activate request. Validate matching drafts, activate staged records, explicitly rollback superseded records, and reserve unchanged for an active equivalent.

**Medium — confirmed.** Finalization moves the staging directory and records checksums but leaves it writable; query/load paths do not verify the manifest (`src/llm_expert_system/storage.py:132-147,192-204`; `src/llm_expert_system/lifecycle.py:209-216`). Publish content-addressed read-only blobs and verify checksums before load/execution.

## Interfaces and configured ceilings diverge

**Medium — confirmed.** CLI arguments are strings and support one capability, without negation, typed values, proof/models, optimization, or max results (`src/llm_expert_system/cli.py:99-116`); React exposes four of six capabilities and the same string-only request (`web/src/App.tsx:25-40`). Configured query timeout/output/model ceilings are unused because client fields and hardcoded broker defaults win (`src/llm_expert_system/config.py:25-29`; `src/llm_expert_system/lifecycle.py:213-221`). Share one request contract and enforce `min(client_request, configured_limit)` server-side.

## Installer and CI guarantees stop before production

**Medium — confirmed.** Docker apt packages, Linux distro packages, Windows winget manifests, and GitHub Action major tags float (`Dockerfile:30-32`; `scripts/install.sh:17-22`; `scripts/install.ps1:16-30`; `.github/workflows/ci.yml:17-18,35-36,50-52`). Pin actions by SHA and production OS sources/versions, then verify installed tool versions.

**Medium — confirmed.** The Docker CI job builds and runs `llm-expert diagnostics`, but never starts authenticated Uvicorn, verifies static assets/Compose restrictions, queries Prolog, or feeds invalid IR through activation (`.github/workflows/ci.yml:49-54`). Add production-profile and negative security smoke tests. Ruff, strict mypy, 20 backend tests (77% coverage), and the Docker image build passed locally; npm dependency retrieval was blocked by the machine certificate chain, while the cached Docker frontend build succeeded.
